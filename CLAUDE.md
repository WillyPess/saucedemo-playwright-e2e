# Sauce Labs E2E Test Suite

Playwright + TypeScript end-to-end suite for the Sauce Labs demo shop
([saucedemo.com](https://www.saucedemo.com)), with a living test plan and bug registry
published to GitHub Pages.

## Stack

Playwright Test + TypeScript, Page Object Model, Node (LTS in CI). No runtime dependencies;
dev dependencies are `@playwright/test`, `@types/node` and `typescript` (type-checking only).

## Folder layout

| Path | What it holds |
|------|---------------|
| `pages/` | Page objects: Login, Inventory, Cart, Checkout, CheckoutStep2, Menu, ProductDetail |
| `tests/e2e/` | Specs: login, inventory, cart, checkout, menu, product-detail (22 tests) |
| `tests/data/` | Centralized test data: `users.ts` (demo accounts), `messages.ts` (expected UI copy), `products.ts` (catalog names, prices, tax rate) |
| `test-plan/index.html` | Hand-maintained living test plan (25 cases, test IDs, status) and Bug Registry |
| `docs/` | README images: `demo.gif`, test plan and bug registry screenshots |
| `playwright.config.ts` | `baseURL` saucedemo.com; Chromium, Firefox, WebKit; list, HTML and JUnit (`test-results/junit.xml`) reporters |

## Commands

- `npm install` then `npx playwright install` - dependencies and browsers
- `npm test` - full suite, all three browsers
- `npm run test:chromium` - what CI runs
- `npm run test:ui` - interactive UI mode
- `npm run report` - open the last HTML report
- `npm run typecheck` - `tsc --noEmit` over config, page objects and specs

## CI

`.github/workflows/playwright.yml` runs on push and pull requests to `main`/`master`:
`npm ci`, typecheck, install browsers, run Chromium only, upload `playwright-report/` as an artifact.
On push to `main` it also assembles `site/` (report + test plan) and publishes it to the
`gh-pages` branch (https://willypess.github.io/saucedemo-playwright-e2e/).

## Env vars

Only `CI` (set by GitHub Actions): enables `forbidOnly`, 2 retries and 1 worker. No secrets;
the saucedemo accounts in `tests/data/users.ts` are the site's public demo users.

## Gotchas

- When tests are added or their status changes, update `test-plan/index.html` (counts,
  IDs, Bug Registry) and the coverage numbers in `README.md` so they stay in sync.
- `gh-pages` is generated by CI; don't edit it by hand.
- Locally tests run fully parallel across three browsers; CI runs serially on Chromium only.
